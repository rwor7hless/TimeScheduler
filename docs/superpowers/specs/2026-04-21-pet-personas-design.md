# Pet Personas — дизайн

**Дата:** 2026-04-21
**Скоуп:** бекенд-промпт `/api/reports/daily-tip` + контракт ответа + интеграция фронта с переменной «персоной» кота.
**Статус:** черновик, ждёт review пользователя.

## Цель

Превратить ежедневное напутствие от ASCII-кота из одной «бесперсонной» LLM-реплики в **узнаваемую бригаду из 5 котов-смен**. Каждый день пользователь видит одного из них — с собственным лицом, именем, голосом и подписью. Это делает питомца одновременно:

- **полезнее**: каждая персона тянет промпт в свою сторону (ворчун видит просрочки, философ — смыслы, минималист — приоритет), поэтому advice получается разный и не размытый;
- **прикольнее**: «сегодня у меня Шпрот» — ритуал, который продукт превращает в привычку;
- **компактнее**: жёсткий двухуровневый формат (`short ≤ 100` + `long ≤ 260` символов) ломает текущую проблему, где модель игнорирует «2-3 предложения» и выдаёт башни.

## Не-цели

- Перекраивать `chat_completion` или LLM-провайдера. Используем существующий `backend/app/services/gigachat.py`.
- Менять кеширование на клиенте. `useDailyTip` остаётся с 1-дневным localStorage кешем.
- Отдельные аватары/картинки котов. Только ASCII-лицо + подпись именем.
- Добавлять новых котов пользователю. Набор зашит на 5.

## 1. Персоны

Каждый кот — комбинация: **имя**, **signature-глаза** (override стандартного `o.o`), **голос** (секция в system-промпте), **триггер-веса**.

| id         | Имя       | Signature    | Голос                                                                                                    | Триггер-вес                                                                                                     |
|------------|-----------|--------------|----------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------|
| `suhar`    | Сухарь    | `(¬.¬)`      | ворчун. Короткие обрубленные фразы, вздохи. Любит подсвечивать просрочки. Без драмы, с усталостью.        | base 1.0; overdue ≥ 1 → ×3. При 0 overdue может всё равно выпасть (1×), но редко.                                |
| `valeryan` | Валерьян  | `(°.°)`      | философ-абсурдист. Всё — метафора. Задачи «пахнут», время «капает». Абсурд + внезапно практичный вывод.   | base 1.0, без модификаторов.                                                                                     |
| `blin`     | Блин      | `(-.-)`      | дзен-минималист. Ровно одно предложение в short, одно-два в long. Винни-Пух-экономия слов.                | base 1.0; если задач ≥ 5 → ×2 (при перегрузе приходит тот, кто сокращает).                                       |
| `shprot`   | Шпрот     | `(•̀.•́)`    | нуар-детектив. Циничный внутренний монолог, «я видел такие списки». Подозревает задачу, расследует привычку. | base 1.0; если дедлайнов сегодня ≥ 2 → ×1.5.                                                                     |

> **Про глаза.** Поля `eyes_l`/`eyes_r` — строки, которые могут состоять из **1–2 unicode-кодпойнтов** (база + комбинирующая метка): например, `•̀` = `U+2022` + `U+0300`. Контракт: «рендерится как один глиф». Фронт просто подставляет строку в шаблон лица, не пытаясь разбирать посимвольно.
| `plyushka` | Плюшка    | `(◡.◡)`      | тёплый остряк. Дружелюбный подкол, без сарказма. Может похвалить, но без «молодец!».                      | base 1.0; утром (5-11 ч локально) → ×1.5; если все задачи/привычки вчера закрыты → ×2 (награда).                 |

### Пример short/long (иллюстрация тона, не эталон)

```
Сухарь    · short: "Опять «8щ68д76» на доске. Она уже прописалась."
          · long:  "Опять «8щ68д76» на доске. Она уже прописалась. Закрой или перенеси — хватит на неё смотреть."

Валерьян  · short: "Утро пахнет чайником и несделанным отчётом."
          · long:  "Утро пахнет чайником и несделанным отчётом. Кот-я считает, что второе мешает первому."

Блин      · short: "Одна задача. Закрой. Остальное подождёт."
          · long:  "Одна задача. Закрой её. Остальное подождёт — и уже привыкло."

Шпрот     · short: "Три встречи и ни одной причины их не отменить. Подозрительно."
          · long:  "Три встречи и ни одной причины их не отменить. Я видел такие расписания — они ломаются на второй."

Плюшка    · short: "Медитация в списке — это уже половина медитации."
          · long:  "Медитация в списке — это уже половина медитации. Вторая половина — не забыть про неё к вечеру."
```

## 2. Алгоритм выбора персоны на день

1. Бекенд собирает контекст дня (как сейчас: tasks, habits, deadline_today, overdue).
2. Вычисляет веса по таблице выше.
3. Взвешенный random.choice по весам — возвращает `persona_id`.
4. Выбор детерминируется **датой + user_id** через `random.Random(seed)`, где seed — стабильный 32-битный int из `hashlib.sha256(f"{user_id}:{iso_date}".encode()).digest()[:4]`. Важно: **не** `hash(...)` — Python рандомизирует его между процессами (PYTHONHASHSEED), это бы давало разного кота при каждом рестарте сервера. Стабильный sha256 гарантирует:
   - в течение дня один и тот же кот, даже через рестарт сервера;
   - между пользователями одна и та же дата даст разных котов;
   - после полуночи кот сменится.

Сиды нужны, чтобы не пришлось персистить выбор в БД — контекст и так кеширует `useDailyTip` на день, а сид-детерминизм страхует от рассинхрона, если кеш сбросится.

## 3. Контракт API

Эндпоинт **не меняет путь**: `GET /api/reports/daily-tip`.

### Response (success)

```json
{
  "date": "2026-04-21",
  "persona": {
    "id": "shprot",
    "name": "Шпрот",
    "eyes_l": "•̀",
    "eyes_r": "•́"
  },
  "short": "Три встречи и ни одной причины их не отменить. Подозрительно.",
  "long": "Три встречи и ни одной причины их не отменить. Я видел такие расписания — они ломаются на второй."
}
```

### Response (LLM отключён)

```json
{
  "date": "2026-04-21",
  "disabled": true,
  "persona": null,
  "short": null,
  "long": null
}
```

### Response (ошибка LLM)

Возвращается HTTP 503 как сейчас. Фронт показывает короткую фразу из локального пула (эта логика уже есть в `AsciiPet` как fallback, будет сохранена).

### Миграция совместимости

Текущий ответ: `{"tip": "...", "date": "..."}`. Новый: `{"short", "long", "persona", "date"}`. Фронт и бекенд обновляются одним PR, старого поля `tip` больше нет. Старый кеш в localStorage неактуален — при первом заходе после деплоя кеш инвалидируется (ключ меняется, см. §5).

## 4. Промпт

### System-промпт (общая шапка для всех персон)

Остаются жёсткие правила как сейчас (русский, без markdown/эмодзи, запрещённые штампы, «не выдумывай задачи»), **но переписаны** для двухуровневого формата:

```
Ты — один из пяти котов-смен в приложении продуктивности.
Какой именно — скажет user-сообщение.

━━━ ЖЁСТКИЕ ПРАВИЛА ━━━
1. Формат ответа: строго JSON вида
   {"short": "...", "long": "..."}
   Никакого текста до/после, никакого markdown вокруг JSON, никаких ```.
2. Длина:
   - short: 1 предложение, не более 100 символов.
   - long:  1–2 предложения, не более 260 символов.
   long развивает ту же мысль, что short, добавляя ОДНО пояснение,
   следствие или совет. Это не цитата short — это его продолжение
   в том же голосе.
3. Обращение: на «ты», от первого лица (я-кот).
4. Язык: живой. Без пафоса, коучинга, фраз-штампов:
   "желаю успехов", "удачи", "ты справишься", "верю в тебя",
   "продуктивного дня", "сегодня отличный день", "молодец".
5. Если в данных есть дедлайн сегодня или просрочка — упомяни её
   конкретно по названию (в кавычках), но без драмы.
6. Если задач нет — не выдумывай. Скажи это прямо, коротко, в характере.
7. Опирайся ТОЛЬКО на данные в user-сообщении.
```

### Персона-блоки (вставляется в system после жёстких правил)

Каждый кот — ~80-120 слов, описывает голос + примеры + что КАТЕГОРИЧЕСКИ нельзя. Хранится как константы в `backend/prompts/pet_personas.py`:

```python
PERSONAS = {
  "suhar": {
    "name": "Сухарь",
    "eyes": ("¬", "¬"),
    "voice": "Ты — старый ворчун. Говоришь короткими, слегка обрубленными фразами...",
  },
  "valeryan": {...},
  ...
}
```

Сборка финального system: `SYSTEM_HEAD + "\n\n" + PERSONAS[id]["voice"]`.

### User-сообщение

Остаётся как сейчас — блок `━━━ ДАННЫЕ ━━━` с задачами, привычками, дедлайнами, просрочками. В конце добавляется:

```
Ответь JSON-ом {"short": "...", "long": "..."} в голосе персоны,
которая описана в system-сообщении.
```

## 5. Валидация ответа (бекенд)

После `chat_completion`:

1. Попытаться распарсить JSON. Если модель обернула в markdown-```, снять обёртку.
2. Проверить ключи `short`, `long`. Если нет — raise RuntimeError → 503.
3. Обрезать по длине: `short[:100]`, `long[:260]`. (Обрезаем на границе слова, добавляем `…` если обрезали.)
4. Если `short` пустой после обрезки — 503.
5. Вернуть клиенту с `persona` инфо (из таблицы, не от модели — модель имя не сочиняет).

## 6. Фронт

### useDailyTip

- Ключ кеша: `pet_tip_v2_${date}_${username}` (новая версия — старый кеш от `daily_tip_...` не подхватится автоматически, это ок).
- В кеше хранится весь ответ: `{persona, short, long, date}`.
- `tip` больше не возвращает строку — возвращает `{persona, short, long}` или `null`.

### AsciiPet

- Новый prop `persona?: {id, name, eyes_l, eyes_r}`.
- Если `persona` есть — глаза кота в **базовом mood** (`content`) берутся из `persona.eyes_l/eyes_r` вместо дефолтных `o.o`. Другие moods (`sleeping`, `celebrate`, `petted`, …) остаются как есть — они логически важнее персоны.
- Под баблом (или под moodBar) появляется подпись `— {persona.name}` мелким шрифтом. В горизонтальном layout — в правом нижнем углу бабла.
- `tip` prop заменяется на `short` и `long`:
  - В баблe показывается `short`.
  - Если `long !== short` — «ещё» раскрывает в `long` (уже есть механика clamp/expand, переиспользуется).
- Fallback (нет LLM / `disabled: true`): персоны нет, глаза дефолтные, бабл показывает контекстную фразу из локального пула, подписи нет.

## 7. Тестирование

- **Unit (бекенд)**:
  - `pick_persona(ctx)` детерминирован по `(user_id, date)`.
  - Весовая логика: при `overdue=[...]` × 3 шанс Сухаря растёт.
  - Парсер валидации: корректный JSON / JSON в ```-обёртке / битый JSON / пустой short → все ветки.
- **Manual (фронт)**:
  - Пять персон по очереди (через dev-флаг `?persona=suhar`, если добавим — опционально).
  - Переключение dark/light не ломает цвета signature-глаз.
  - Длинный `long` раскрывается «ещё», короткий — нет.
  - Отключённый LLM → fallback работает.

## 8. Открытые вопросы

- **Dev-override персоны через query-param** (`?persona=suhar`) — чтобы легко тестировать все 5 лиц. Добавим? Плюс: удобно. Минус: ещё одна ветка в роутере. **Рекомендация:** добавить, за feature flag/`DEBUG`.
- **Нужна ли «ручная смена» для пользователя?** (кнопка «позови другого кота»). **Рекомендация:** нет на v1 — сюрприз-элемент в том, что ты не выбираешь.
- **Пятая персона Плюшка награждает за «вчера 80%+»** — это требует читать вчерашнюю статистику. У нас уже есть stats service, но вытаскивать это ради веса — overkill на v1. **Рекомендация:** этот модификатор в v1 выкинуть, оставить только утренний ×1.5. Для v2 можно добавить.

## 9. Out of scope для этой итерации

- Аватары/картинки котов помимо ASCII.
- Пользовательская настройка (выключить кота, выбрать любимого).
- Несколько реплик в день от одного кота.
- Озвучка реплик.
